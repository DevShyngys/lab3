# Лабораторная работа 3 — REST API и два сервиса

CSS4004 «Распределённые системы». Приложение из двух независимых сервисов на
Flask. Данные хранятся в памяти процессов, база данных не используется.

| Сервис | Файл | Порт | Назначение |
| --- | --- | --- | --- |
| A — каталог | `catalog_service.py` | 5001 | Товары: создание и получение по id |
| B — заказы | `orders_service.py` | 5002 | Заказы: при создании обращается к A по HTTP |

Сервис B вызывает сервис A по HTTP с таймаутом, получает название и цену
товара, считает сумму и **сохраняет название с ценой внутри заказа**. Поэтому
чтение заказа работает даже при выключенном каталоге.

## Установка

```bash
python3 -m venv venv
source venv/bin/activate          # Windows: venv\Scripts\activate
pip install -r requirements.txt
```

## Запуск

Каждый сервис — отдельный процесс в отдельном терминале.

Терминал 1 — каталог:

```bash
python3 catalog_service.py --port 5001
```

Терминал 2 — заказы:

```bash
python3 orders_service.py --port 5002 --catalog-url http://127.0.0.1:5001 --timeout 2
```

Ключи сервиса B:

| Ключ | Значение |
| --- | --- |
| `--port` | порт сервиса заказов (по умолчанию 5002) |
| `--catalog-url` | адрес сервиса A (по умолчанию `http://127.0.0.1:5001`) |
| `--timeout` | таймаут запросов к A в секундах (по умолчанию 2.0) |

Ключи сервиса A: `--port`, `--no-seed` (не создавать демонстрационные товары),
`--slow N` (задержка ответа на N секунд — для демонстрации таймаута).

## Автоматический прогон трёх проверок

```bash
python3 run_checks.py
```

Скрипт сам поднимает оба сервиса, выполняет проверки, останавливает каталог в
нужный момент и печатает все запросы с ответами. Результат последнего прогона
сохранён в `checks_output.txt`.

## Эндпоинты

### Сервис A — каталог (порт 5001)

| Метод и адрес | Назначение | Коды |
| --- | --- | --- |
| `POST /products` | создать товар, тело `{"name": ..., "price": ...}` | 201, 400 |
| `GET /products/<id>` | товар по идентификатору | 200, 404 |
| `GET /products` | список товаров | 200 |
| `GET /health` | проверка доступности | 200 |

### Сервис B — заказы (порт 5002)

| Метод и адрес | Назначение | Коды |
| --- | --- | --- |
| `POST /orders` | создать заказ, тело `{"product_id": ..., "quantity": ...}` | 201, 400, 404, 503 |
| `GET /orders/<id>` | сохранённый заказ | 200, 404 |
| `GET /orders` | список заказов | 200 |
| `GET /health` | адрес каталога и значение таймаута | 200 |

Коды ответа `POST /orders`:

| Код | Когда |
| --- | --- |
| 201 | заказ создан |
| 400 | некорректное тело: нет `product_id` или `quantity` < 1 |
| 404 | каталог доступен, но товара с таким id нет |
| 503 | каталог недоступен: не запущен или не ответил за время таймаута |
| 502 | каталог ответил, но запись товара без имени или цены |

Разделение 404 и 503 принципиально: в первом случае ошибся клиент, во втором
отказала зависимость сервиса.

## Три проверки

Полный вывод — в файле `checks_output.txt`.

### Проверка 1. Оба сервиса работают

```
$ curl -i -X POST http://127.0.0.1:5001/products \
       -H 'Content-Type: application/json' \
       -d '{"name": "Мышь", "price": 5000}'
HTTP/1.1 201 CREATED
Location: /products/1

{"id": 1, "name": "Мышь", "price": 5000}
```

```
$ curl -i -X POST http://127.0.0.1:5002/orders \
       -H 'Content-Type: application/json' \
       -d '{"product_id": 1, "quantity": 3}'
HTTP/1.1 201 CREATED
Location: /orders/1

{
  "id": 1,
  "product_id": 1,
  "name": "Мышь",
  "price": 5000,
  "quantity": 3,
  "total": 15000
}
```

В ответе есть название товара, цена, количество и итоговая сумма
5000 × 3 = 15000.

### Проверка 2. Каталог остановлен — создание заказа даёт 503

```
$ curl -i -X POST http://127.0.0.1:5002/orders \
       -H 'Content-Type: application/json' \
       -d '{"product_id": 1, "quantity": 2}'
HTTP/1.1 503 SERVICE UNAVAILABLE

{
  "error": "catalog_unavailable",
  "message": "Сервис каталога недоступен: нет соединения с каталогом: ConnectionError"
}
```

Сервис B при этом продолжает работать и отвечает на остальные запросы:

```
$ curl -i http://127.0.0.1:5002/health
HTTP/1.1 200 OK

{"service": "orders", "status": "ok",
 "catalog_url": "http://127.0.0.1:5001", "timeout": 2.0}
```

### Проверка 3. Каталог остановлен — чтение заказа даёт 200

```
$ curl -i http://127.0.0.1:5002/orders/1
HTTP/1.1 200 OK

{
  "id": 1,
  "product_id": 1,
  "name": "Мышь",
  "price": 5000,
  "quantity": 3,
  "total": 15000
}
```

Название и цена берутся из самого заказа — обращения к каталогу здесь нет.

### Дополнительно: несуществующий товар при работающем каталоге

```
$ curl -i -X POST http://127.0.0.1:5002/orders \
       -H 'Content-Type: application/json' \
       -d '{"product_id": 999, "quantity": 1}'
HTTP/1.1 404 NOT FOUND

{"error": "product_not_found", "message": "товар с id=999 отсутствует в каталоге"}
```

### Дополнительно: срабатывание таймаута

Каталог запускается с искусственной задержкой больше таймаута:

```bash
python3 catalog_service.py --port 5001 --slow 5
python3 orders_service.py --port 5002 --timeout 2
```

```
$ curl -i -X POST http://127.0.0.1:5002/orders \
       -H 'Content-Type: application/json' \
       -d '{"product_id": 1, "quantity": 2}'
HTTP/1.1 503 SERVICE UNAVAILABLE

{"error": "catalog_unavailable",
 "message": "Сервис каталога недоступен: каталог не ответил за 2.0 с"}
```

Сервис B прекращает ожидание через 2 секунды, а не висит пять.

## О вызове между сервисами и таймауте

Запрос B → A выполняется функцией `fetch_product()`:

```python
url = f"{CATALOG_URL}/products/{product_id}"
response = requests.get(url, timeout=REQUEST_TIMEOUT)
```

Таймаут обязателен. Без него при зависшем каталоге поток сервиса B ждал бы
ответа неопределённо долго. Запросы накапливались бы, пул потоков Flask
исчерпался бы, и сервис заказов перестал бы отвечать вообще — отказ одного
сервиса обрушил бы второй. Таймаут ограничивает ожидание и превращает отказ
зависимости в обычный ответ 503.

Обрабатываются три разных исхода неудачи:

| Исключение | Причина |
| --- | --- |
| `ConnectionError` | сервис A не запущен или порт недоступен |
| `Timeout` | A запущен, но не ответил за отведённое время |
| `RequestException` | прочие ошибки запроса |

Все три приводят к ответу 503 — для клиента сервиса B разница несущественна,
важно лишь, что причина не в его запросе.

## Использование ИИ

При выполнении работы использовался Claude (Anthropic):

- генерация первоначального кода обоих сервисов и скрипта проверок;
- подбор кодов состояния HTTP для различных видов отказа (503 против 404);
- оформление README.

Код проверен и запущен самостоятельно, все три проверки выполнены локально,
вывод в `checks_output.txt` получен на собственной машине.
